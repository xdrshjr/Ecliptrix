# 数字动画工作台允许编辑对当前模板无效的参数

## 问题描述

在「特效 → 数字动画 → 柱形增长」中，用户可以将「最终数值」改为 777、将「单位」改为 kg。工作台显示「已保存」，生成任务也成功，但三根柱子的标签仍是 30、60、90，成品与修改前逐帧相同。「数字递增」有对应的问题，用户可以修改「三列数值」，生成的视频仍只显示递增数字。

预期是用户在当前模板看到的动画参数都有明确的画面作用。本次使用 Windows、源码基线 `947b99fa`、中文界面的 Chromium、Next.js 开发服务、独立 FastAPI/SQLite 和本地 Remotion 渲染服务。实测覆盖工作台、草稿保存、六次 MP4 生成及一次成品上轨。

## 复现步骤

1. 在具有可用本地渲染组件的编辑器中新建空白视频项目。从素材面板底部打开「特效」，选择「数字动画 → 柱形增长」。画布选 720 × 720，时长填 1 秒后按 Tab。保持标题为空，使用默认配色、速度和强度。
2. 保留默认三列 30、60、90，「最终数值」100，「单位」为空。等顶部显示「已保存」，点「生成视频」，得到 A。将预览拖到时间码 `00:00:06`（第 6 帧，从 0 开始），此时入场动画已完成。
3. 只把「最终数值」改为 777、「单位」改为 kg，按 Tab 并等待「已保存」。再点「生成视频」，得到 B。预览中仍是 30、60、90。作为阳性对照，保留 777 和 kg，把「三列数值 1」从 30 改为 75，保存并生成 C，第一根柱子的标签变为 75。
4. 切换到「数字递增」，等默认参数保存后生成 D。只把「三列数值 1」从 30 改为 75，保存并生成 E；同一帧仍显示 100。把「最终数值」和「单位」改为 777 和 kg，保存并生成 F；同一帧显示 `777kg`。
5. 展开「最近生成」，找到 B 对应的草稿版本，点「在新视频轨插入」，随后关闭工作台。本次空时间线由 0 个片段变为 1 个，片段标示「特效 · 1.0s」。任务卡按新到旧排列，可用版本号识别。

对成品可在 PowerShell 中粘贴以下命令，把路径换为对应的两个 MP4。按解码顺序比较每帧的像素摘要，可以排除文件名和容器元数据差异。

```powershell
function Get-FrameHashes($path) {
    $lines = & ffmpeg -v error -i $path -map 0:v:0 -an -f framemd5 -
    if ($LASTEXITCODE -ne 0) { throw "视频解码失败：$path" }
    $lines | Where-Object { $_ -match '^\s*\d+,' } | ForEach-Object { ($_ -split ',')[-1].Trim() }
}
$first = @(Get-FrameHashes 'A.mp4')
$second = @(Get-FrameHashes 'B.mp4')
if ($first.Count -ne 30 -or $second.Count -ne 30) { throw '两个样本都应有 30 帧' }
@(0..29 | Where-Object { $first[$_] -ne $second[$_] }).Count
```

## 根因分析

| 实测成品 | 任务快照中的模板参数 | 与上一对照样本相比，像素不同的帧 |
|---|---|---|
| A，版本 2，柱形增长 | 100、空单位、[30, 60, 90] | 基线 |
| B，版本 3，柱形增长 | 777、kg、[30, 60, 90] | A → B 为 **0 / 30** |
| C，版本 4，柱形增长 | 777、kg、[75, 60, 90] | B → C 为 **30 / 30** |
| D，版本 5，数字递增 | 100、空单位、[30, 60, 90] | 基线 |
| E，版本 6，数字递增 | 100、空单位、[75, 60, 90] | D → E 为 **0 / 30** |
| F，版本 7，数字递增 | 777、kg、[75, 60, 90] | E → F 为 **30 / 30** |

六个渲染任务均为 `succeeded`。对每组相邻对照，比对了任务保存的 `render_snapshot.document`，除 `params` 外其余字段完全相同。沿任务的 `result_asset_id` 找到对应成品后解码，A 和 B 的第 6 帧摘要都是 `88869a6e93baf9583e403a6840c590ab`，C 的同一帧是 `ce2b90e4d3b67259472acd38e4eabc42`。六个视频、测试数据库、比对脚本 `compare.py` 和原始输出 `observed.txt` 在本次任务的 `.agentmesh/task-tge-446712a4-7641-4f55-9098-8957288fcff4/scratch/round3-counters/`。

1. **参数从哪里来。** 两个模板的 v1 目录都声明了 `value`、`suffix`、`bars`，且都有默认值（`src/lib/effects/catalog.json:846`、`src/lib/effects/catalog.json:906`）。规格把两个视觉变体和三种参数列在同一行（`docs/plans/remotion-effects-studio/spec.md:334`）。
2. **为何界面允许编辑。** 检查器直接遍历 `Object.entries(template.parameterSchema)`，为每个字段生成控件。数组每项有自己的数值框，字符串和数字分别写回同一份草稿（`src/components/video/effects/EffectsInspector.tsx:82`、`src/components/video/effects/EffectsInspector.tsx:91`、`src/components/video/effects/EffectsInspector.tsx:95`、`src/components/video/effects/EffectsInspector.tsx:102`）。界面因此把文档允许存储的每个字段都呈现为可调效果。
3. **为何成品没有变化。** `Counters` 按模板 ID 选择绘制分支。「柱形增长」用 `bars` 计算柱高与数字标签（`src/lib/effects/compositions/Counters.tsx:11`、`src/lib/effects/compositions/Counters.tsx:15`），「数字递增」用 `value` 和 `suffix` 生成显示文字（同文件第 22–24 行）。预览播放器和离线渲染组合都使用 `EffectComposition`（`src/components/video/effects/EffectsPreview.tsx:32`、`src/lib/effects/compositions/EffectRoot.tsx:10`）。这解释了同一个字段在两个模板上的相反结果，也与成功保存的快照和逐帧对照一致。

## 影响面

使用这两个模板的用户可以反复保存、生成和插入视觉完全相同的版本。「单位」尤其容易误导，例如想表达 kg 的用户会得到没有单位的柱形标签。已确认的范围是这两个模板的参数编辑、工作台预览和本地生成的 MP4。本轮验证到了插入时间线，未测试安装包或整条时间线的最终导出。

## 候选修复方案

| 方案 | 改动范围 | 风险与代价 | 预计工作量 |
|---|---|---|---|
| A．按模板筛选检查器显示的参数 | 在检查器生成字段前，给这两个模板指定实际可编辑的键。「数字递增」显示最终数值和单位，「柱形增长」显示三列数值，其他模板沿用现有逻辑 | 低。保留 v1 草稿、冻结的生成请求和既有画面。需用这两个模板的测试约束字段列表与绘制逻辑，防止以后脱节 | 小，集中在前端和定向测试 |
| B．拆分两个模板的参数契约 | 在共享目录中分别声明各自实际消费的参数，同步处理旧草稿读取、生成请求恢复和目录导出 | 中高。前端严格解析字段，后端会拒绝未知参数，直接删键会使带旧字段的 v1 文档失效（`src/lib/effects/validation.ts:63`、`backend-services/basic-service/app/services/effects/catalog.py:90`） | 较大，涉及模板版本、兼容读取和跨端回归 |

## 推荐修复与验收

推荐 **A**。用户当前需要知道改哪个字段才能改动画。现有两个绘制分支都已给出可验证的正确结果，调整字段展示就能消除误导，同时保留已有作品的视觉和草稿兼容性。

验收时打开带全部三个旧字段的 v1 草稿，分别用鼠标和键盘切换两个模板。检查各自有效的控件可见、可聚焦，未展示的字段不会因打开或保存而被删除。按上述 C 和 F 的输入各生成一次，核对第 6 帧的第一根柱子显示 75、递增数字显示 `777kg`，并确认关闭重开后仍可编辑和生成。

## 评审结论

**采纳方案 A，在检查器按当前模板 ID 展示参数。** 「柱形增长」只展示 `bars` 的三个输入框，「数字递增」只展示 `value` 和 `suffix`。从当前草稿直接派生字段列表，沿用原有的控件、数值提交和只读逻辑。其他模板继续按目录展示。适用范围是这三个模板专属参数，六份样本均使用默认的通用运动设置。

**成品与执行路径。** 评审重新运行了留存的 `compare.py`。脚本按每个成功任务的 `result_asset_id` 读取其 MP4，核对快照，再用 FFmpeg 解码全部 180 帧。四组对照依次有 0、30、0、30 帧发生变化。版本 3 和 6 的快照已有用户输入，排除了这两次编辑在失焦或保存时丢失。两个阴性对照覆盖完整成品，两个阳性对照在同样的采样条件下产生了变化，因此该现象也能在预览播放器之外独立复核。两次同时调整数值和单位的实验只能证明组合结果，各字段的作用可从实际绘制分支分别确认。

工作台将同一份草稿交给检查器和播放器（`EffectsStudioModal.tsx:181–193`）。生成时先刷新草稿，按保存成功的版本提交（`useEffectsController.ts:295–303`）。后端从该任务的快照构造渲染文档（`backend-services/basic-service/app/services/effects/job_service.py:413–417`），运行时把同一组 `inputProps` 交给组合选择和 H.264 编码（`effects-runtime/src/renderChild.ts:195–205`）。两个目录项的 `componentId` 均为 `Counters`（`src/lib/effects/catalog.json:849、909`），组合按该键分派并传入文档（`EffectComposition.tsx:23–33、50–53`）。柱形分支逐列计算高度与标签，数字分支拼接数值与单位（`Counters.tsx:11–28`）。完整 `params` 虽然参与文字布局缓存键，文字内容仍由分支传入的文本或标题决定（`EffectText.tsx:18–25`）。这解释了参数能保存、能触发布局重算，却对最终像素没有作用。

**旧草稿的修正入口。** 本地工作副本允许保留越界值供用户修正。现有测试就用柱形模板恢复了负数、超长单位和越界柱值（`src/lib/effects/__tests__/pendingWrites.test.ts:85–95`）。恢复会将原文档放回编辑器，保存时才执行完整校验（`useEffectsDraft.ts:180、275–283`）。例如旧版用户能在柱形模板输入九个字符的单位；若新版直接隐藏单位，预览和生成都会被校验拦住（`EffectsStudioModal.tsx:46–51、185`）。仅当隐藏参数自身违反目录约束时，在可编辑草稿中提示具体字段，并提供显式的「恢复该参数默认值」操作，复用普通草稿编辑及撤销流程。这样也能修正长度错误的隐藏数组。打开、重绘或校验失败时均应保留原值，合法的隐藏参数随草稿原样保存。

**方案取舍与验收边界。** 在 v1 目录删键会同时影响前端严格解析、后端未知键检查及本地恢复时的键数量核验（`src/lib/effects/validation.ts:55–64`、`backend-services/basic-service/app/services/effects/catalog.py:89–95`、`src/lib/effects/pendingWrites.ts:37–47、76–80`）。改动绘制语义也会改变已有作品，例如版本 3 的柱形标签会凭空多出 kg。两者都超出本次界面修复所需。

验收时应区分两类操作。打开旧草稿、同模板内编辑或撤销，应保留合法的隐藏值；主动切换到另一模板则沿用现有的模板默认值，重选同模板仍为空操作（`useEffectsController.ts:284–293`）。快速切换或撤销后，检查 Tab 顺序与当下模板一致；旧保存响应返回后，生成快照应对应最终保存的版本。用超长单位的本地柱形草稿验证显式修正后可恢复预览、保存和生成，再用合法的非默认隐藏值验证打开及修改可见参数均不会覆盖它。只读视图应可查看诊断，所有编辑和修正操作均随现有字段组禁用（`EffectsInspector.tsx:16–24`）。

## 修复验证

- 检查器按模板选择可编辑字段，保留 v1 参数结构。旧草稿中的隐藏参数沿用保存时的校验规则。用户可以逐项恢复非法值的默认值，并通过撤销取回原值。
- 复跑特效组件与核心库的 14 个测试文件，110 项全部通过。回归用例从本地工作副本恢复负数、超长单位和长度错误的柱值数组，覆盖只读状态、逐项修正、撤销，以及对原草稿版本的保存。用例使用非默认的相邻参数，以便发现误覆盖。
- 按任务记录关联成品，用 FFmpeg 重新解码修复后生成的 6 份 MP4。柱形样本与上表 C 对照，递增样本与 F 对照，180 帧逐帧一致。前序实测还覆盖关闭重开、延迟保存后生成和插入新视频轨。本轮复核使用留存成品。
