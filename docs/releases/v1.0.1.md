## 3. 第一轮冒烟为什么失败（环境，不是包）

```
[smoke-test] FAIL: Error: unexpected llm-status payload
(want success=true configured=false): {"success":true,"data":{"configured":true,"source":"environment"}}
```

原因是**发布者的 shell 里导出了真实的 `LLM_API_KEY` / `LLM_API_URL`**，被测应用作为子进程
继承了它们，于是 `GET /api/config/llm-status` 如实回答「已配置，来源：environment」——
这与「`.env` / 环境变量回退」这条文档化的行为一致，产品没有缺陷。

重跑方式（`desktop/cache/release-prep/run-smoke-keyless.ps1`，未入库）：先清掉 12 个凭证形状
的环境变量（只打印键名，不打印值），再在同一个 `release/win-unpacked` 上跑门禁。这一轮
`PASS`。也就是说：门禁测的是「零凭证」状态，而这一状态必须由调用方保证，门禁自身只写空
`.env`，管不了继承来的环境变量。

**这条值得进下次的发布清单**：门禁启动前先确认进程环境里没有厂商凭证变量，否则会得到
一个假的红灯。
