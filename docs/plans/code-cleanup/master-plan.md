# Master Plan: 全栈废弃代码清理

## 概述

对 Ecliptrix 项目进行全面的废弃代码扫描和清理，覆盖前端（Next.js 15 / TypeScript / React）和后端（FastAPI / Python），目标是消除所有未使用的代码、注释掉的代码块、废弃的 API 路由和未使用的依赖包，保持 clean code 状态。

## 目标

1. **消除死代码**：删除所有未被引用的组件、函数、hooks、服务、类型定义、变量
2. **清理注释代码**：移除所有被注释掉的代码块（依赖 git 历史回溯）
3. **清理废弃路由**：找出前端 API 路由与后端路由之间不再匹配/使用的废弃路由
4. **清理未使用依赖**：移除 `package.json` 和 `requirements.txt` 中未被使用的依赖包
5. **清理未使用导入**：移除所有文件中未使用的 import 语句

## 范围

### 纳入范围（In Scope）

| 区域 | 路径 | 检查内容 |
|------|------|----------|
| 前端组件 | `src/components/` | 未使用的组件、hooks、服务函数 |
| 前端类型 | `src/types/`, 各组件内 types | 未导出/未引用的类型定义 |
| 前端 API 层 | `src/lib/api/` | 未被调用的 API 客户端函数 |
| 前端上下文 | `src/contexts/` | 未使用的 context 值或方法 |
| Next.js API 路由 | `src/app/api/` | 不再被前端调用的路由 |
| 后端路由 | `app/routers/` | 不再被前端 API 路由代理的端点 |
| 后端服务 | `app/services/` | 未被路由调用的服务方法 |
| 后端模型 | `app/models/` | 未被使用的 Pydantic 模型/字段 |
| 依赖包 | `package.json`, `requirements.txt` | 未在代码中被 import 的依赖 |
| 注释代码 | 全项目 | 所有被注释掉的代码块 |

### 排除范围（Out of Scope）

- 代码重构（DRY 优化、架构调整）
- 性能优化
- 安全审计
- 测试用例编写
- 配置文件清理（`.env`、YAML config）
- `__pycache__`、`.pyc` 文件清理（gitignore 问题，不在此次范围内）

## 架构决策

### 扫描策略

```
全栈扫描（并行）
├── 前端扫描
│   ├── 1. 未使用导入检查（ESLint + grep）
│   ├── 2. 未使用组件/函数/hooks 检查（导出引用交叉分析）
│   ├── 3. 未使用类型定义检查
│   ├── 4. 废弃 API 路由检查（前端调用 vs API 路由定义）
│   ├── 5. 注释代码块扫描
│   └── 6. 未使用 npm 依赖检查
├── 后端扫描
│   ├── 1. 未使用导入检查
│   ├── 2. 未使用函数/类/方法检查
│   ├── 3. 未使用模型字段检查
│   ├── 4. 废弃后端路由检查（对比前端代理路由）
│   ├── 5. 注释代码块扫描
│   └── 6. 未使用 Python 依赖检查
└── 交叉验证
    └── 前后端路由对应关系验证
```

### 执行原则

1. **安全第一**：对每个待删除项确认无引用后才执行删除
2. **最小影响**：每次改动只删除确认废弃的部分，不改变现有功能
3. **可验证**：删除后通过 TypeScript 类型检查和 Python 语法检查验证无破坏
4. **依赖 git**：所有删除操作均可通过 git 历史回溯

## 依赖与风险

### 依赖

- ESLint 配置已就绪（项目已有）
- TypeScript 编译器可用（`npm run type-check`）
- Python 环境可用（后端 venv）

### 风险

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 动态 import 导致误删 | 中 | 检查 `dynamic()` 和字符串拼接的导入路径 |
| 反射/字符串引用的函数 | 低 | 对后端路由注册、装饰器使用做额外检查 |
| i18n key 引用导致误判 | 低 | 不删除 i18n 相关代码 |
| 删除后类型检查失败 | 中 | 每批删除后运行 `npm run type-check` 验证 |
