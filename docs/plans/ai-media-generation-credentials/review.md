## 本轮已修复的问题

以下 15 类问题均已直接修改源码并用回归复现；没有将代码问题留作待办。

| 编号 | 问题与修复 |
|---|---|
| CR-01 | 普通／逐句占位实际保存在 React 本地状态，但完成校验读取 Zustand 素材，可能丢弃已受理任务 ID。改为读取真实本地素材快照，测试使用真实 React state。 |
| CR-02 | 普通生成卸载后遗留 pending。停止本地请求并记录明确终态，重挂载清理无拥有者占位；稳定标记同时覆盖逐句来源。 |
| CR-03 | 全局 poller 先跳过在途请求，挂起查询可以越过十分钟期限。先检查期限并中止查询。 |
| CR-04 | 持久化逐句 generating 在重新打开项目后永久等待。项目载入时仅将中断的逐句状态转为 failed，保留已有素材、脚本与恢复备份。 |
| CR-05 | 模型变更后不支持的已选尾帧被隐藏。保留已选尾帧槽，允许用户移除。 |
| CR-06 | 预置默认下，已保存自定义模型未出现在目录，Agent 无法合法单次覆盖。目录包含有效已保存自定义项。 |
| CR-07 | 自定义默认 ID 与预置重名时，公开能力与实际解析不一致。目录、默认解析和显式覆盖使用一致能力，未启用草稿不改变预置行为。 |
| CR-08 | 无效环境模型在 select 中误显示首个有效预置。保留真实无效值并标记无效状态。 |
| CR-09 | base64 长度预判错误拒绝实际低于大小上限的图片。修正编码边界，仍按实际解码字节数拒绝达到上限的输入。 |
| CR-10 | 分镜失败过早删除原生终态，普通查询可能隐式重新下载。保留已脱敏终态及重新收取冷却。 |
| CR-11 | sbv 成功快照在缓存删除后仍返回 ready。分镜查询复用原生缓存指纹和后台重新验证。 |
| CR-12 | 显式重新收取后，后续 sbv 查询仍返回旧 failed。同步队列状态并继续跟随原生任务。 |
| CR-13 | 分镜提交网络超时或队列期限到达时丢失受理未知语义。未取得 ID 的提交使用 generation_submission_unknown，不重复收费。 |
| CR-14 | 已完成超过 30 分钟的缓存复验继承旧期限并立即超时。只为已完成任务的本地复验重设期限，不延长原始生成期限。 |
| CR-15 | 分镜创建的鉴权、限流、模型未开通错误被统一吞为生成失败。提取并复用现有错误分类，保留受控错误码，测试同时检查单次 POST 和正文不泄露。 |

超出原文件表的最小必要改动是 `useMaterialManagement.ts` 传递本地素材引用，以及 `VideoEditorContainer.tsx` 调用新的纯恢复函数；新增独立回归文件覆盖分镜生命周期和逐句载入恢复。其余扩展范围沿用 `spec.md` 的实施缺陷记录。
