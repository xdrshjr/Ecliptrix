# AI 图片／视频独立凭证实施验收

验收日期：2026-11-05（美国纽约时间）。依据同目录 `spec.md` v2。本节为上一实施节点的验收记录，该节点未执行 Git 提交；最终代码审查、补充修复及验证见 [review.md](review.md)。

## 实施结果

- 设置和引导分别提供 `ark_image`、`ark_video`；图片旧配置仅作一次迁移，视频不会读取图片 Key 或旧共享 Key。
- 视频支持三个预置模型和自定义模型／接入点能力配置；目录读取、配置修订检查、能力约束在收费提交之前执行。
- 所有生成入口采用同一完成条件：供应商成功后，下载、完整 FFmpeg 解码、缓存写入及校验完成，才返回本地 `ready`。真实时长和宽高随状态传递，缩略图失败不阻挡视频完成。
- 创建任务不自动重试。状态查询有明确期限和有限重试；在途任务保留原配置快照；终态、取消、TTL、关机释放快照与协程。
- 普通素材、逐句、脚本、分镜及 Agent 已接入。素材使用原生任务 ID 判重，切项目／删占位／卸载后不消费迟到结果。提交中切换脚本标签再返回时，无 ID 的遗留任务提示受理未知，不永久转圈或自动重提。
- 配置竞争保留草稿并刷新模型目录。产物失败可在任务提示中显式重新收取同一任务，绝不重新创建收费任务。
- 请求校验错误、供应商错误经过受控脱敏；模型目录和设置响应均不返回 Key。

## 真实供应商调用

隔离后端：`127.0.0.1:18321`，数据库 `data/ark-video-acceptance/dev.db`，文件根目录 `data/ark-video-acceptance/storage`。本机默认 Python 的 OpenCV 导入异常，实际应用使用仓库已有桌面包中的 Python 启动，仍加载本次修改后的后端源码；未安装依赖。

用户凭证只读查询官方 `/api/v3/models` 返回 HTTP 200。公开返回中有 2.0 标准、Fast、Mini 及 1.0 Lite，没有 `2.0 lite`。这不能证明任意型号的收费权限，亦不能将 1.0 Lite 或其他型号映射为用户口述的 2.0 lite。

隔离设置 API 保存视频 Key 和默认模型 `doubao-seedance-2-0-260128` 返回 200；保存前后图片均未配置，视频由未配置变为可用。真实 Key 不写入源码、环境模板、测试夹具或本文；完整任务 ID 只留在忽略目录证据中。

实际生成脚本只调用本地应用，携带当前配置修订，提交一次 5 秒、720p、16:9、纸船水面场景。收费创建总计一次，不切模型试错，不因超时新建。

首次供应商生成成功后，安全下载器拒绝了本机代理 DNS 返回的非公网地址（`dns_answer_non_global`），状态正确为 `video_download_failed`，没有伪造完成。只读诊断确认本机已有 `127.0.0.1:7897` 系统代理，手动开发后端未获得桌面程序通常注入的该配置。通过隔离实例已有网络设置 API 沿用该代理后，显式 `retry_artifact=true` 重新收取**同一个原任务**成功；没有关闭 SSRF 检查、修改正式设置或新建收费任务。
