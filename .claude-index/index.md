## Project Overview

- **Type:** Electron desktop app (Next.js renderer + local FastAPI service), single monorepo
- **Languages:** TypeScript (~76% of 2,605 source files: 1,421 `.ts` + 566 `.tsx`), Python (~19.5%: 508 `.py`), JavaScript/ESM (~4%: 92 `.js` + 18 `.mjs`, Electron shell + build scripts)
- **Frameworks:** Next.js 15 (App Router) + React 19 + FastAPI + Electron (electron-builder); Remotion 4.0.544 / React 19.1.1 in `effects-runtime/` for the effects worker
- **Entry Points:**
  - Frontend: `src/app/page.tsx`, `src/app/layout.tsx`
  - Backend: `backend-services/basic-service/app/main.py` (`run.py`)
  - Desktop: `desktop/main/index.js` (Electron main), `desktop/preload/preload.js`
- **Database:** SQLite via async SQLAlchemy + aiosqlite. No PostgreSQL, no Alembic — the schema is built by `create_all` at startup plus an idempotent ownership `UPDATE`; tests use SQLite in-memory
- **UI:** shadcn/ui (new-york style), Tailwind CSS 3, class-based dark mode
- **State:** React Context (Locale / Notification / Session) + Zustand (`useVideoEditingStore`, `useTimelineStore`, `editorFocusStore`, `exportSessionStore`)
- **i18n:** English + Chinese in one file (`src/lib/i18n.ts`, ~13.6k lines)
- **Auth:** two layers, neither one a data-access control. (1) A **desktop identity gate** in the Electron main process (`desktop/main/auth*.js`) holds the tokens, so the renderer only ever sees a redacted `AuthStatus`; business rows keep `user_id = LOCAL_OWNER_ID`. (2) A **separate account server** in `webserver/` owns identity. The local FastAPI backend still has no user system, session or RBAC, binds to `127.0.0.1`, and no route takes an auth dependency (`app/constants.py`, mirrored in `src/lib/localOwner.ts`)
- **Testing:** Vitest (frontend, **650** test files under `src/`), pytest (backend, **212** `test_*.py` in `backend-services/basic-service/tests/`), **28** test files in `webserver/`, `desktop/main/*.test.js` node:test suites, plus the packaged-app smoke test
- **Deployment:** desktop only — `electron-builder` installer; there is no server deployment path for the app itself. `webserver/` deploys separately (Dockerfile + compose + systemd unit)
- **Scale:** **2,605** source files (TS/TSX/PY/JS/MJS) across **3,379** files; **140** Next.js API routes under `src/app/api`, **43** `*.py` files in `app/routers/` (41 feature routers) wired by **42** `include_router` calls plus one self-registering router, **22** ORM tables across 5 model modules, **110** backend service modules in 9 subpackages, **15** service YAML configs, **84** plan folders under `docs/plans/`, and the separate account-server subproject (`webserver/`: 269 files, 48 API routes, 22 pages, 5 migrations)
- **Effects:** `src/lib/effects/` (catalog + text layout, the single sources of truth) → `effects-runtime/` (Remotion worker) → `app/services/effects/` (drafts, render jobs, assets)

## Account Server (`webserver/`)

A **separate, independently deployable** Next.js 15 project that owns user
identity for the desktop app (269 files: 80 under `src/app/`, 48 in
`src/components/`, 59 in `src/server/`, 28 tests). It is a standalone npm
project — never import `@/*` from the root `src/`, never add root dependencies to
it. Blueprint: `docs/plans/webserver-user-management/spec.md`; its tail sections
「实施过程发现的方案缺陷」 and 「代码评审」 record every deliberate deviation.

- **Stack:** App Router + TypeScript + React 19 + Tailwind 3, SQLite via
  `better-sqlite3` (WAL), hand-written SQL migrations (`0001_init` …
  `0005_account_lifecycle`), opaque tokens (**no JWT**), scrypt passwords. No
  Prisma / Drizzle / NextAuth
- **Layering is enforced:** `app/**/page.tsx` (RSC) calls `server/services/*`
  directly and never fetches its own API; `app/api/v1/**/route.ts` only parses,
  `zod`-validates, takes a guard and calls a service; SQL exists only in
  `server/db/repositories/*`
- **Two guards, one place:** `requireAdminWrite()` (permission → CSRF →
  `admin:write` budget) / `requireAdminRead()` in `server/auth/guards.ts` —
  never hand-rolled in a route
- **Bearer vs cookie:** the desktop sends `Authorization: Bearer` and is exempt
  from CSRF; the browser uses the `ecs_session` cookie plus a double-submit
  `X-CSRF-Token`. The response shape follows the **token carrier**
- **Mail is a pipeline:** `server/mail/mailer.ts` is only the SMTP transport;
  `mailService.queue()` is the single exit (render → outbox row → one bounded
  attempt → outcome). "No SMTP" is a supported mode (`captured` rows)
- **Three partial unique indexes carry invariants:** `idx_email_action_live`,
  `idx_deletion_live`, and the nullable
  `account_deletion_requests.token_hash` — read the predicate before touching the
  writers
- **Deletion anonymises, never deletes** (`status='deleted'`, tombstone address)
- Scripts: `db:migrate`, `db:prune`, `accounts:sweep`, `user:create`, `user:reset`,
  `user:verify`, `account:confirm-deletion`, `node scripts/smoke.mjs` (109
  end-to-end assertions against a running server)
- Deploy: `Dockerfile`, `docker-compose.yml`,
  `deploy/{nginx.conf.example,webserver.service}` — single writer only; scaling
  out requires PostgreSQL

## Storage Model

- **Primary:** local filesystem under `STORAGE_ROOT` (default `static/uploads`). Static mounts: `/api/storage/files`, `/api/audio/generated`, `/api/audio/subtitles`, `/static/timeline_exports`.
- **Layout:** `static/uploads/{video,audio,images,files}`, `static/video/{composed,thumbnails}`, `static/audio/{generated,subtitles}`, `static/timeline_exports`, `temp/`, `logs/`
- **Cached remote materials:** `STORAGE_ROOT/cached_materials/<source>/<source_id>.<ext>`, tracked in the `cached_materials` table, served through the existing `/api/storage/files` mount. Frontend derives `local_url` as `/api/storage/files/cached_materials/<source>/<basename>`. Web-research downloads land here too, via `web_media_download.download_material()`.
- **Agent workspace:** a separate per-project sandbox root owned by `agent_toolkit/workspace_store.py` (quota + `max_file_bytes` enforced in `agent-toolkit-config.yaml`), with paged reads so no tool call has to hold a whole file.
- `MATERIAL_DOWNLOAD_MAX_CONCURRENT` (default 4) caps the background download semaphore. ARK/storyboard videos write back via `material_svc.store_external_download_async(..., source='ark', source_id=<task_id>)`.
- No cloud object storage — this is a self-contained local desktop app.

## Shipping

There is no server deployment: Ecliptrix ships as an Electron desktop app, so
"shipping" means building an installer, not provisioning a host.

- `cd desktop && npm run build` — installer (prepare-env -> prepare-frontend -> prepare-backend -> electron-builder)
- `cd desktop && npm run build:dir` — unpacked build, the input to the smoke test
- `node desktop/scripts/smoke-test.js` — end-to-end gate on the packaged app
- `node desktop/scripts/verify-research-release.js` — research/browser capability gate
- Dev stack: `cd desktop && npm run dev` (Electron + backend + Next dev server), or
  `uvicorn app.main:app --host 127.0.0.1 --port 8000` from `backend-services/basic-service/`
  plus `npm run dev` at the repo root for the browser debugging path
